# EA Issue #61 / PR #62 paired recovery trial

## Setup

- Date: 2026-08-13
- Project and feature: `jayjcc8-cloud/ea-quant`, Issue #61 / PR #62 lifecycle coordinator
- Frozen candidate: `43637b76ec23023e21afc56a38f9864e498ccb77`
- Participant/agent configuration: six Codex collaboration tasks in isolated clean worktrees
- Plugin version: `0.3.0+codex.20260811105542`
- Comparison: three baseline tasks created without the plugin and three governed tasks created with distinct actors, work units, checkpoints, and bindings
- Controls: all six tasks used the same frozen commit and the same recovery request; no source, spec, test, runtime-execution, or GitHub writes were permitted during the timed turn

## Outcomes

| Metric | Baseline | Governed |
|---|---:|---:|
| Raw recovery times | 112.711s, 117.869s, 120.674s | 121.829s, 154.843s, 145.954s |
| Median | 117.869s | 145.954s |
| Correct authority result | 3/3 | 3/3 |
| Explicit bindings found | n/a | 1/3 |
| Strict resumes completed | n/a | 1/3 |
| Actor/session leaks | 0 | 0 |

The governed median was 23.827% slower. The executable summary returned `effect_not_demonstrated`: the five-minute absolute bound passed, but the declared 50% relative improvement threshold failed.

All six tasks correctly recovered the frozen HEAD, clean worktree, closed Issue #61, merged PR #62, accepted ADR 0021, zero unresolved review threads, and a terminal next action. No authority drift was injected in this frozen trial, so undetected-drift performance remains unmeasured here.

## Failure retained

All three governed bindings were present and actor-isolated, but only one task resolved its current binding. The public CLI exposed `bind` and `unbind` but no safe read-only binding-resolution command. One task found its binding with an internal helper; two tasks correctly refused to scan `.agent-runtime` and fell back to full authority reconstruction. This is recorded as `ACTIVE_SESSION_BINDING_RESOLUTION_INCONSISTENT`, not discarded as setup noise.

The bound sample also repeated remote reads after strict resume, so a valid checkpoint did not yet reduce the requested evidence-gathering work enough to improve latency.

## Conclusion

Accuracy and actor isolation passed. Recovery-time benefit and binding discovery did not. The current release is suitable only for advisory shadow use; it must not gate deployment, autonomous continuation, or production changes.

Product changes triggered by this trial:

1. Add a read-only `resolve-binding` command keyed by the current session and optional subagent ID, with no fallback.
2. Require the Skill to use `CODEX_THREAD_ID`, never the delegated source task ID.
3. Re-run the same paired recovery design after packaging the fix.
4. Add a separate controlled authority-drift trial before any V1 decision.

## Post-fix forward test

The `resolve-binding` fix was packaged as `0.3.0+codex.20260813133346` and forward-tested in three fresh collaboration tasks. All three resolved only their own session binding, completed strict resume, returned the correct authority state, and showed no actor/session leakage. Binding reliability therefore improved from 1/3 to 3/3.

Recovery times were 142.422s, 135.291s, and 133.699s (median 135.291s). Against the original 117.869s baseline median, this is 14.781% slower, so the effect verdict remains `effect_not_demonstrated`. The remaining cost is dominated by strict remote authority refresh plus separate review-thread/Issue evidence reads that are not covered by the checkpoint digest.

The packaging pass also exposed an operational constraint: active desktop tasks pin the plugin cache path loaded by their host. Removing the installed plugin before adding a new cachebuster deleted that pinned path and produced repeated Stop-hook failures. Restoring the old path ended the loop. Local development updates must run cachebuster + `codex plugin add` without first removing the active version, and must retain old cache paths until their tasks end.
